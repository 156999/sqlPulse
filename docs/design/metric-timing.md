# 监控指标的时间和统计口径

## 时间来源

- SQL 汇总和分语句曲线：使用 Locust `stats_history.csv` 的 `Timestamp`（秒级）。
  它表示生成统计快照的时间；SQL 请求在完成时计入统计，不代表单次 SQL 的开始时间。
- SQL `collected_at`：平台读到该记录的时间，独立于横轴。历史重建无法知道当时的采集时间，留空。
- MySQL、主机、异常采样：使用实际采样时间 `resource_collected_at`，保留小数秒。
- 历史任务的旧资源记录保留原时间和原值，不根据 SQL 时间平移，也不补造资源样本。

## 采集与结束补齐

SQL 历史存入独立 `sql_metrics` 表，以 `(run_id, ts)` 唯一定位快照。
增量读取器保留文件偏移，每轮处理所有新增完整行，半行留到下一轮读取。
同秒重复快照以最新内容为准；重复轮询、刷新和 SSE 重放不会增加重复曲线点。
数据库写入失败时重置文件检查点，重读后由唯一键去重。

Locust 子进程通过 `configure_csv_history()` 把 CSV 写入和 flush 间隔设为 1 秒。
其 CSV writer 在正常退出关闭文件前额外记录一次终态历史，并重写最终汇总、失败和异常文件。
平台等待子进程退出后，先补读历史，再公开结束状态、生成快照与报告。
强制终止进程无法保证执行关闭钩子；只能恢复已写出的完整记录。

客户端结束时重新加载汇总曲线、分语句曲线和事件时间线。
时间点按数值时间戳排序和更新，横轴使用真实时间距离，间隔超过 2.5 秒断线。

## 指标口径

| 指标 | 口径 |
| --- | --- |
| SQL QPS | Locust 近期已完成秒桶的平滑速率；不是单秒瞬时值 |
| SQL P95/P99 | Locust 近约 10 秒的滚动窗口 |
| SQL 平均延迟、错误率、请求数 | 从任务开始累计 |
| MySQL 计数器速率 | 两次有效采样的计数器差 / 单调时钟间隔 |
| 主机磁盘、网络吞吐 | 字节计数器差 / 实际间隔 |
| 最终汇总卡片 | `stats.csv` 的累计统计 |

MySQL 首次采样或计数器重置时不生成虚假的零速率。
报告累计计数按速率乘实际间隔还原；平均 MySQL QPS 按间隔加权。
旧任务没有保存准确的采样间隔，不追溯修改其原始 MySQL 增量。

## 历史兼容

读取已结束任务时，可从已有 CSV 重建 SQL 时间线。
合并接口按时间组合独立 SQL 和资源序列，并屏蔽旧记录中错误使用采集时间的 SQL 值。
原始 `metrics` 和 CSV 保留；范围查询不会把旧 SQL 值重新暴露出来。
若原 CSV 缺失，保留旧数据，无法恢复其真实 SQL 时间。
旧 CSV 没有记录的尾部窗口、单次请求时间和资源指标，无法凭最终累计值反推。

此修改没有恢复已撤销的结果一致性卡片、采集异常计数、滞后点或采样年龄统计。
