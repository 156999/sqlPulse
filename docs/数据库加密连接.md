# 数据库加密连接方案设计

## 1. 背景

当前 SQL Pulse 中存在两类密码，安全策略不同：

### 1.1 SQL Pulse 登录密码

登录密码通过 `pwdlib` 的推荐哈希算法保存，当前为 Argon2id 格式：

```text
$argon2id$v=19$...
```

数据库只保存 `users.password_hash`，不能从哈希中还原原始密码。初始测试账号为 `root / root`，生产环境必须修改或停用该默认账号。

### 1.2 MySQL 连接密码

连接管理和任务快照当前直接保存 MySQL 密码，主要位置包括：

- `mysql_connections.password`
- `runs.db_dsn_json.password`
- `datagen_jobs.target_dsn_json.password`

这会导致任何能够读取 `data/sqlpulse.db`、数据库备份或任务快照的人都可能获得目标 MySQL 连接密码，属于明文凭据风险。

## 2. 目标

- MySQL 连接密码不再以明文写入 SQLite、任务快照或日志。
- 压测、造数和连接测试仍能正常解密并连接目标数据库。
- SQL Pulse 登录密码继续采用不可逆哈希，不改为可解密加密。
- 浏览器不保存连接密码，API 响应不返回连接密码。
- 支持历史明文数据迁移、密钥轮换和迁移失败恢复。
- 不影响旧任务的查询、报告和已有连接管理流程。

## 3. 安全边界

```text
SQL Pulse 登录密码：Argon2id 哈希，不可逆
MySQL 连接密码：Fernet 对称加密，可解密使用
APP_SECRET_KEY：用于 Session 签名，不作为数据库凭据加密密钥
SQLPULSE_CREDENTIAL_KEY：专门用于 MySQL 密码加密
```

登录密码和 MySQL 密码必须使用不同的密钥和不同的存储策略。

## 4. 加密方案

### 4.1 算法

使用项目已经声明的 `cryptography` 依赖和 Fernet：

```python
from cryptography.fernet import Fernet

cipher = Fernet(settings.credential_key.encode())
ciphertext = cipher.encrypt(password.encode("utf-8")).decode("ascii")
plaintext = cipher.decrypt(ciphertext.encode("ascii")).decode("utf-8")
```

Fernet 提供：

- AES 对称加密
- 完整性校验
- 密文篡改检测
- 版本化密文格式

密码为空字符串时也应加密，不能通过空值绕过存储策略。

### 4.2 密钥配置

新增环境变量：

```env
SQLPULSE_CREDENTIAL_KEY=生成的Fernet密钥
```

生成命令：

```powershell
.\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

要求：

- 密钥只放在部署环境变量或受控密钥管理服务中。
- 不写入 SQLite、代码、前端、日志或 Git。
- `.env` 必须加入 `.gitignore`。
- 生产环境和测试环境使用不同密钥。
- 缺少密钥时，启用认证的生产环境应拒绝启动，而不是回退到明文。

### 4.3 密钥版本

为支持轮换，建议密文增加版本信息：

```text
v1:gAAAAA...
```

配置可以扩展为：

```env
SQLPULSE_CREDENTIAL_KEY_VERSION=v1
SQLPULSE_CREDENTIAL_KEYS_V1=...
SQLPULSE_CREDENTIAL_KEYS_V2=...
```

读取时根据密文前缀选择密钥；写入时始终使用当前版本。

## 5. 数据模型改造

### 5.1 连接表

将字段语义从 `password` 调整为密文：

```sql
ALTER TABLE mysql_connections ADD COLUMN password_ciphertext TEXT;
```

迁移完成后：

- 新代码只写 `password_ciphertext`。
- `password` 仅用于一次性历史迁移。
- 迁移完成后将 `password` 更新为空字符串，或删除该字段。
- 查询连接时不向前端返回密码或密文。

### 5.2 任务快照

`runs.db_dsn_json` 和 `datagen_jobs.target_dsn_json` 不再保存明文密码。

推荐保存：

```json
{
  "host": "127.0.0.1",
  "port": 3306,
  "user": "root",
  "password_ciphertext": "v1:gAAAAA...",
  "database": "sqlpulse_ecommerce"
}
```

任务快照必须保存执行所需的连接信息，但密码只能是密文。读取任务详情、报告和列表时，统一过滤 `password`、`password_ciphertext` 等字段。

## 6. 服务层设计

新增统一服务，例如 `app/services/credential_crypto.py`：

```python
class CredentialCrypto:
    def encrypt(self, value: str) -> str: ...
    def decrypt(self, value: str) -> str: ...
    def is_encrypted(self, value: str) -> bool: ...
```

服务层规则：

- 路由层不直接调用 Fernet。
- 数据库写入前统一加密。
- 数据库读取后仅在真正建立 MySQL 连接前解密。
- 解密失败返回明确错误，但不把密文或明文写入日志。
- 任何 `to_public_connection()`、任务详情和报告序列化都必须删除密码字段。

连接使用流程：

```text
用户提交密码
  -> 路由校验
  -> credential_crypto.encrypt
  -> 写入 mysql_connections.password_ciphertext

压测/造数启动
  -> 读取密文
  -> credential_crypto.decrypt
  -> 组装临时 DSN
  -> 建立 MySQL 连接
  -> 连接使用完成后释放明文对象
```

## 7. API 行为

### 7.1 创建和修改连接

请求仍允许用户提交明文密码，但只在 HTTPS 请求处理期间存在：

```json
{
  "name": "电商测试库",
  "host": "127.0.0.1",
  "port": 3306,
  "user": "root",
  "password": "用户输入的密码",
  "database": "sqlpulse_ecommerce"
}
```

响应只能返回：

```json
{
  "id": "...",
  "name": "电商测试库",
  "host": "127.0.0.1",
  "port": 3306,
  "user": "root",
  "database": "sqlpulse_ecommerce",
  "has_password": true
}
```

禁止返回：

- 原始密码
- 密文
- 完整 DSN
- 包含密码的异常信息

### 7.2 编辑连接

- 页面密码框默认为空。
- 空密码表示保留原密码，不覆盖已有密文。
- 用户填写新密码时重新加密并覆盖旧密文。
- 提供“清除密码”操作时，必须要求用户确认，并在后续连接测试前提示缺少密码。

### 7.3 临时连接

临时连接密码只用于当前请求和运行快照生成：

- 不写入浏览器 `localStorage`。
- 不写入明文任务快照。
- 任务创建前加密后保存密文快照。
- 任务结束后不额外复制密码。

## 8. 历史数据迁移

迁移必须是一次性、可审计、可恢复的操作。

### 8.1 迁移步骤

1. 检查 `SQLPULSE_CREDENTIAL_KEY` 是否存在。
2. 备份 SQLite 数据库文件。
3. 新增 `password_ciphertext` 字段。
4. 逐行读取旧明文密码并加密。
5. 更新连接表和任务快照中的密码字段。
6. 验证所有密文能够解密。
7. 清空旧明文字段。
8. 写入迁移版本和完成时间。
9. 迁移完成后禁止旧代码路径写入明文。

### 8.2 迁移失败

- 单条记录失败不得静默跳过。
- 迁移应记录失败记录 ID，不记录密码内容。
- 失败时保留备份，不删除原数据库。
- 服务应进入“凭据迁移未完成”状态，禁止继续写入新明文。

## 9. 日志与前端脱敏

以下内容禁止进入日志：

- 数据库密码
- `password`、`password_ciphertext`
- 带密码的 DSN
- 完整 `TARGET_DB_PASSWORD` 环境变量
- PyMySQL 连接异常中包含的完整连接字符串

日志中可以记录：

```text
连接名称、主机、端口、数据库名、用户名、has_password、错误类型
```

错误示例：

```text
数据库连接失败：Access denied for configured database user
```

不得输出具体密码或完整 DSN。

## 10. Session 与登录密码

SQL Pulse 登录密码继续使用 Argon2id 哈希：

```python
hash_password(password)
verify_password(password, password_hash)
```

登录密码不使用 Fernet，因为登录时不需要还原原密码。`APP_SECRET_KEY` 只用于 Session 签名，不能复用为 MySQL 密码加密密钥。

默认 `root / root` 仅用于本地测试：

- 生产环境首次启动必须要求修改默认密码，或关闭默认账号种子。
- 不在部署文档和生产日志中输出默认密码。
- 增加密码强度和首次登录修改密码流程。

## 11. 密钥轮换

轮换流程：

1. 生成新的 Fernet 密钥。
2. 保留旧密钥用于读取旧密文。
3. 读取并解密所有现有连接密码。
4. 使用新密钥重新加密。
5. 更新密文版本前缀。
6. 验证所有连接可测试成功。
7. 切换到新密钥并撤销旧密钥。

密钥丢失时无法恢复 MySQL 密码，系统应要求用户重新填写连接密码。

## 12. 测试方案

### 12.1 单元测试

- 明文加密后不等于原文。
- 正确密钥可以解密。
- 错误密钥解密失败。
- 密文被修改后解密失败。
- 空密码也能正确加密和解密。
- 密钥缺失时生产配置拒绝启动。
- 连接响应不包含密码和密文。

### 12.2 集成测试

- 创建连接后检查 SQLite 不包含原始密码。
- 使用保存连接测试数据库成功。
- 使用保存连接创建压测任务成功。
- 使用保存连接创建造数任务成功。
- 历史明文连接迁移后仍可连接。
- 任务详情、监控、报告和下载接口均不泄露密码。
- 新旧密钥轮换后任务仍可使用。

### 12.3 安全回归

使用以下方式检查泄露：

```powershell
rg -n "password|TARGET_DB_PASSWORD|db_dsn_json" logs data
```

检查结果中不得出现真实密码。测试数据使用专用假密码，不使用生产凭据。

## 13. 实施顺序

1. 新增凭据加密服务和环境配置。
2. 改造连接表写入、读取和连接测试流程。
3. 改造压测任务和造数任务快照。
4. 增加历史明文迁移命令。
5. 统一 API、日志、模板和报告脱敏。
6. 增加密钥轮换能力。
7. 完成单元测试和集成测试。
8. 生产部署前关闭默认 `root / root` 或强制修改密码。

## 14. 验收标准

- SQLite 中不再出现新的 MySQL 明文密码。
- `mysql_connections`、`runs`、`datagen_jobs` 中的密码均为密文或不存在。
- 保存连接、压测和造数功能正常。
- SQL Pulse 登录密码仍以 Argon2id 哈希保存。
- 前端、API、日志和报告均不返回密码。
- 缺少加密密钥时生产环境拒绝启动。
- 历史数据可完成迁移并通过连接测试。
- 密钥轮换后所有有效连接仍可正常使用。
