# sample 外键优化方案

## 一、背景

单表造数读取数据库元数据后，外键字段应生成数据库中真实存在的父表键值。目前规则处理中，外键字段会先切换为 `sample`，但当字段参与唯一索引时又可能被切回随机生成，导致生成不存在的父表 ID，最终触发外键约束错误。

本方案将“字段值合法”和“唯一组合不重复”拆分处理：外键负责值域合法性，唯一索引负责单值或组合去重，不能通过禁止所有 sample 来代替唯一性计划。

## 二、目标

- 外键字段自动从被引用表、列抽样。
- 单列唯一字段避免重复使用已有值。
- 联合唯一索引按完整字段组合去重，不禁止每个成员字段 sample。
- 用户点击“应用数据库规则”后获得明确、可执行的最终生成计划。
- 页面只展示原始规则到最终规则的净变化。
- 执行失败时日志能够定位约束、候选值、组合和重试次数。

## 三、规则优先级

```text
字段可插入性
> 外键合法性
> 单列唯一性
> 联合唯一性
> 用户显式配置
> 数据库类型默认规则
```

优先级说明：

1. 自增列、生成列和未显式覆盖的默认值列优先跳过。
2. 外键字段的值必须来自父表被引用列，不能使用任意随机值。
3. 单列唯一字段必须保证该字段值不与存量数据及任务内数据重复。
4. 联合唯一索引只约束完整组合，不要求每个成员字段单独唯一。
5. 用户规则只能在满足数据库硬约束的范围内生效。

## 四、外键 sample 规则

读取 `information_schema.KEY_COLUMN_USAGE`，为每个外键建立抽样来源：

```json
{
  "column": "order_id",
  "generator": "sample",
  "sample_source": {
    "table": "ec_orders",
    "column": "id"
  },
  "sample_ratio": 100,
  "reason": "外键 ec_order_items.order_id 引用 ec_orders.id"
}
```

处理要求：

- 默认使用父表被引用列作为唯一抽样来源。
- 外键模式下 `sample_ratio` 固定为 100%，不使用随机回退值。
- 父表无可用数据时，在提交前阻止任务并提示具体外键。
- 任务开始时预加载受控样本缓存，执行期间不逐行查询父表。
- 抽样结果保持数据库原始类型，不做字符串拼接。
- 多个字段引用同一父表列时共享任务级样本缓存。

## 五、唯一性策略

### 1. 单列唯一

对于主键或单列唯一索引：

- 普通 sample 默认禁用，因为重复抽取已有值必然可能冲突。
- 字符串字段优先使用高熵随机字符串或 UUID，并限制到字段长度。
- 数字字段优先使用序列或不重复随机池。
- 任务开始前可按需加载数据库已有值或检查候选空间。
- 任务内维护 `used_values[column]`。
- 发生冲突时重新生成，达到最大重试次数后停止并报告。

如果单列唯一字段同时是外键，则使用“父表不放回抽样”：

- 从父表键集合中依次取未使用值。
- 生成条数不能超过可用父键数量。
- 提交前计算可用空间，不足时直接阻止任务。

### 2. 联合唯一

例如：

```sql
UNIQUE KEY uk_order_sku (order_id, sku_id)
```

字段生成方式保持：

```text
order_id = sample(ec_orders.id)
sku_id   = sample(ec_product_skus.id)
```

唯一性在组合层处理：

```text
unique_key = (order_id, sku_id)
```

执行要求：

- 任务开始时读取或分页加载数据库已有组合。
- 任务内维护 `used_combinations[index_name]`。
- 每次生成完整行后再计算组合键。
- 组合已存在时，只重新生成该唯一索引涉及的字段。
- 同一行涉及多个唯一索引时，必须全部通过后才能执行 INSERT。
- 达到最大重试次数后停止，并报告索引名称、候选组合和已重试次数。

联合唯一组合空间估算：

```text
理论组合空间 = 各成员字段候选数量的乘积
可用组合空间 = 理论组合空间 - 数据库已有组合数 - 任务内已使用组合数
```

生成条数超过可用空间时，应在提交前阻止任务。

## 六、应用数据库规则

用户点击“应用数据库规则”后，服务端重新读取表结构并输出统一执行计划。

以 `ec_order_items` 为例：

```json
{
  "fields": [
    {
      "column": "order_id",
      "generator": "sample",
      "sample_source": {"table": "ec_orders", "column": "id"}
    },
    {
      "column": "sku_id",
      "generator": "sample",
      "sample_source": {"table": "ec_product_skus", "column": "id"}
    }
  ],
  "unique_plans": [
    {
      "index": "uk_ec_order_items_order_sku",
      "columns": ["order_id", "sku_id"],
      "strategy": "combination_deduplicate",
      "max_retries": 20
    }
  ]
}
```

表单必须回写最终字段规则，并增加“约束策略”区域：

| 约束 | 字段 | 最终策略 |
|---|---|---|
| 外键 | order_id | 从 ec_orders.id 抽样 |
| 外键 | sku_id | 从 ec_product_skus.id 抽样 |
| 联合唯一 | order_id + sku_id | 组合去重，冲突重试 20 次 |

## 七、净变化展示

页面只展示用户原始配置和最终规则之间的净变化，不展示规则引擎的中间步骤。

正确示例：

```text
order_id：随机整数 -> 从 ec_orders.id 抽样
sku_id：随机整数 -> 从 ec_product_skus.id 抽样
quantity：1～100000 -> 1～32767
联合唯一 order_id + sku_id：已启用组合去重
```

以下内容不应展示：

```text
rand -> sample -> rand
0 -> "0"
1000 -> "1000"
```

比较规则时需先做类型规范化，例如数字字符串 `"1000"` 与数字 `1000` 视为相同值。

## 八、执行流程

1. 读取目标表字段、外键、主键和唯一索引。
2. 编译字段生成器和外键 sample 来源。
3. 建立单列唯一计划和联合唯一组合计划。
4. 预加载父表键值、存量唯一值和存量唯一组合。
5. 生成一行候选数据。
6. 校验字段类型、外键和非空等约束。
7. 校验单列唯一值和联合唯一组合。
8. 冲突时重新生成受影响字段，最多重试配置次数。
9. 校验通过后绑定参数并执行 INSERT。
10. 成功后把唯一值和组合加入任务级已用集合。

并发任务仍以数据库唯一索引和外键约束作为最终裁判。遇到并发冲突时允许有限重试，不能绕过数据库约束。

## 九、日志要求

外键和唯一性相关日志至少包含：

```text
generated-row 37/100
foreign-key order_id -> ec_orders.id, sampled=12345
foreign-key sku_id -> ec_product_skus.id, sampled=678
unique-index uk_ec_order_items_order_sku, candidate=(12345,678)
duplicate combination, retry=2/20
```

最终失败日志包含：

- 生成行序号和 SQL 模板序号。
- 外键名称、来源表和来源列。
- 冲突的唯一索引名称。
- 脱敏后的候选值或组合。
- 当前重试次数和最大重试次数。
- MySQL 错误码和错误消息。

## 十、安全与性能

- 表名和列名必须来自数据库元数据并进行标识符校验。
- sample 查询使用参数化条件和数量上限。
- 敏感字段默认禁止抽样，日志中必须脱敏。
- 大表的已有唯一组合应分页加载、使用哈希摘要或按需查询，避免一次性占用过多内存。
- 任务级缓存结束后立即释放，不跨用户或任务共享原始样本值。
- 组合去重集合应设置内存上限，超限时切换为数据库临时表或批量存在性查询。

## 十一、分阶段实施

1. 修正规则优先级：外键字段参与联合唯一时继续使用父表 sample。
2. 增加净变化比较，移除中间变化和数字类型转换噪声。
3. 实现任务级联合唯一组合去重和冲突重试。
4. 实现数据库已有组合预加载与可用空间检查。
5. 实现单列唯一外键的不放回抽样。
6. 增加约束策略展示、预览和详细执行日志。

## 十二、验收标准

- 外键字段生成值 100% 存在于父表被引用列。
- 参与联合唯一索引的外键字段不会被改回任意随机生成。
- 同一任务内不生成重复的联合唯一组合。
- 能识别并避开数据库已有的联合唯一组合。
- 生成条数超过可用组合空间时，在提交前明确阻止。
- 页面只显示原始规则到最终规则的净变化。
- 相同元数据和相同用户规则重复应用时结果幂等。
- 冲突日志可以定位索引、候选组合、生成行和重试次数。
