# SQL Pulse MySQL 连接管理设计方案（V1）

- 状态：Draft
- 日期：2026-09-18
- 范围：MySQL 连接 CRUD、用户级连接隔离、压测与造数任务复用连接、历史任务快照
- 关联实现：`app/db.py`、`app/models.py`、`app/routers/tasks.py`、`app/routers/datagen.py`、`app/routers/pages.py`、`app/services/*`
- 关联页面：`app/templates/new_run.html`、`app/templates/datagen.html`
- 关联文档：`sqlpulse/docs/auth_design.md`、`sqlpulse/docs/datagen_design.md`

## 1. 背景与问题

当前压测和造数各自维护一套 MySQL 连接入口：

- 压测页 `app/templates/new_run.html` 有独立的 `host/port/user/password/database` 表单。
- 造数页 `app/templates/datagen.html` 重复同一套表单。
- 两页各自用 `localStorage` 保存上次输入，只对当前浏览器生效，换用户、换浏览器、清缓存都会丢失。
- `app/routers/tasks.py` 和 `app/routers/datagen.py` 各自实现了几乎相同的 `pymysql` 连接测试逻辑。
- `app/models.py` 虽然复用了 `DbDsn`，但连接没有归属、没有管理入口、不能跨任务复用。

因此需要把“MySQL 连接”从任务表单里的临时输入，提升为平台内可复用、按用户隔离、可管理的资源。

## 2. 目标

### 2.1 V1 目标

- 用户可以在平台内创建、编辑、删除、测试自己的 MySQL 连接。
- 不同用户的连接互相隔离，只能看到自己创建的连接。
- 压测和造数页通过“选择已保存连接”发起任务，不再重复填写连接信息。
- 连接管理服务由压测、造数共用，消除重复的连接测试与 DSN 解析逻辑。
- 历史任务继续保留创建时的 DSN 快照；连接后续修改或删除不影响历史任务。
- 对现有数据库、历史任务和已有 API 保持兼容。

### 2.2 V1 不实现

- 连接共享给其他用户。
- 多 MySQL 实例的集群级连接管理。
- MySQL 密码云端托管、KMS、外部密钥服务。
- 连接健康巡检、自动探活告警。
- 根据连接自动发现库表、字段、索引。
- 把历史任务快照中的密码统一迁移或加密改写。

## 3. 功能需求

### FR-1 连接列表

- `GET /connections` 渲染连接管理页面。
- `GET /api/connections` 返回当前用户的连接列表。
- 列表字段：`id`、`name`、`host`、`port`、`user`、`database`、`created_at`、`updated_at`、`has_password`。
- 列表不返回 `password`。

### FR-2 新建连接

- `POST /api/connections` 创建连接。
- 必填：`name`、`host`、`user`、`database`。
- 默认值：`port=3306`、`password=""`。
- 连接名称在当前用户下唯一，去首尾空格。
- 创建时可选择立即测试连接，也可以只保存不测试。

### FR-3 编辑连接

- `PUT /api/connections/{connection_id}` 更新连接。
- 只能更新当前用户自己的连接。
- 更新规则：
  - `password` 为空字符串表示保持原密码不变。
  - `host`、`port`、`user`、`database` 按提交内容更新。
- 更新后刷新 `updated_at`。

### FR-4 删除连接

- `DELETE /api/connections/{connection_id}` 删除当前用户自己的连接。
- 删除只移除连接定义，不删除历史任务以及历史任务中的 DSN 快照。

### FR-5 测试连接

- `POST /api/connections/{connection_id}/test` 用已保存连接测试。
- `POST /api/connections/test` 用临时 DSN 测试，供“不使用已保存连接”场景使用。
- 测试只执行 `SELECT 1`，不创建表、不写数据。
- 测试失败返回 `{"ok": false, "error": "..."}`，错误信息不包含密码。

### FR-6 压测接入

- 新建压测页增加“使用已保存连接 / 临时连接”两种模式。
- 使用已保存连接时，提交 `connection_id`，前端不提交具体 DSN。
- 使用临时连接时，保留现有表单输入，提交 `db_dsn`。
- 后端解析出完整 `DbDsn` 后，继续把 DSN 快照写入 `runs.db_dsn_json`。

### FR-7 造数接入

- 新建造数页采用与压测页相同的连接选择模式。
- 使用已保存连接时提交 `connection_id`。
- 使用临时连接时提交 `db_dsn`。
- 后端解析出完整 `DbDsn` 后，继续把 DSN 快照写入 `datagen_jobs.target_dsn_json`。

### FR-8 历史兼容

- `runs.db_dsn_json` 和 `datagen_jobs.target_dsn_json` 是任务快照，保持 JSON 结构不变。
- 历史任务继续按快照展示连接信息，不读取“我的连接”中的最新配置。
- 现有只填 `db_dsn` 的请求继续可用，不强制升级到 `connection_id`。

## 4. 数据设计

### 4.1 新增表 `mysql_connections`

```sql
CREATE TABLE IF NOT EXISTS mysql_connections (
  id          TEXT PRIMARY KEY,
  user_id     TEXT NOT NULL,
  name        TEXT NOT NULL,
  host        TEXT NOT NULL,
  port        INTEGER NOT NULL DEFAULT 3306,
  user        TEXT NOT NULL,
  password    TEXT NOT NULL DEFAULT '',
  database    TEXT NOT NULL,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  UNIQUE (user_id, name)
);

CREATE INDEX IF NOT EXISTS idx_mysql_connections_user
  ON mysql_connections (user_id);
```

说明：

- `user_id` 与 `auth_design.md` 中的 `users.id` 对齐。
- `UNIQUE (user_id, name)` 保证同一用户不重复保存同名连接。
- `name` 是用户可读标识，例如 `订单库`、`压测环境-主库`。
- `password` 以明文存放在 SQL Pulse 本地 SQLite 中，与当前任务快照一致。V1 接受该风险，加密存储放入 V2。

### 4.2 原有表不做破坏性迁移

- `runs` 表保留 `db_dsn_json`，继续作为压测任务快照。
- `datagen_jobs` 表保留 `target_dsn_json`，继续作为造数任务快照。
- 不在 V1 给历史表增加非空约束或改写历史 JSON。

### 4.3 可选：任务与连接关联

V1 任务快照已经满足语义，但为了后续排查“这个任务当时选了哪条连接”，可给两张任务表增加可空列：

```sql
ALTER TABLE runs ADD COLUMN connection_id TEXT;
ALTER TABLE datagen_jobs ADD COLUMN connection_id TEXT;
```

该列仅做追溯，不作为任务执行时的数据来源；任务执行始终使用快照 DSN。此步骤可选，若 V1 希望最小改动也可以暂不实施。

### 4.4 匿名模式

`AUTH_ENABLED=false` 时不存在真实 `user_id`，连接统一归属固定匿名空间：

- 使用哨兵值 `anonymous` 作为 `user_id`。
- 所有未登录用户共享 `anonymous` 空间下的连接。
- 后续重新启用 `AUTH_ENABLED=true` 后，匿名连接仍存在但不进入任何真实用户的列表中，避免越权。
- 如需把匿名连接迁移给真实用户，可作为后续管理功能处理。

## 5. 接口设计

### 5.1 连接管理 API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/connections` | 当前用户的连接列表 |
| `POST` | `/api/connections` | 新建连接 |
| `GET` | `/api/connections/{id}` | 当前用户单条连接详情 |
| `PUT` | `/api/connections/{id}` | 更新连接 |
| `DELETE` | `/api/connections/{id}` | 删除连接 |
| `POST` | `/api/connections/{id}/test` | 测试已保存连接 |
| `POST` | `/api/connections/test` | 测试临时 DSN |

所有 `/api/connections/*` 接口沿用现有 `require_user` 依赖。

### 5.2 请求模型

```python
class ConnectionCreate(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    host: str = Field(min_length=1, max_length=255)
    port: int = Field(default=3306, ge=1, le=65535)
    user: str = Field(min_length=1, max_length=255)
    password: str = Field(default="", max_length=1024)
    database: str = Field(min_length=1, max_length=255)


class ConnectionUpdate(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    host: str = Field(min_length=1, max_length=255)
    port: int = Field(ge=1, le=65535)
    user: str = Field(min_length=1, max_length=255)
    password: str = Field(default="", max_length=1024)
    database: str = Field(min_length=1, max_length=255)
```

### 5.3 任务请求模型变更

`TaskCreate` 和 `DataGenJobCreate` 增加可选 `connection_id`：

```python
class TaskCreate(BaseModel):
    name: str
    sql_source: str = "paste"
    sql_content: str
    concurrency: int
    spawn_rate: int
    duration_sec: int
    connection_id: Optional[str] = None
    db_dsn: Optional[DbDsn] = None


class DataGenJobCreate(BaseModel):
    name: str
    mode: Literal["sql", "shell"]
    source: Literal["paste", "file"] = "paste"
    content: str
    connection_id: Optional[str] = None
    db_dsn: Optional[DbDsn] = None
```

校验规则：

- `connection_id` 与 `db_dsn` 至少提供一个，二者都为空时返回 400。
- 二者都提供时优先使用 `connection_id`，或直接返回 400 避免歧义；V1 建议直接返回 400。
- `connection_id` 必须属于当前用户。
- 使用 `connection_id` 成功后，后端把解析出的 DSN 序列化写入原快照字段。

### 5.4 DSN 解析规则

```text
请求 -> 校验
  -> 使用 connection_id 时：
       SELECT host, port, user, password, database
       FROM mysql_connections
       WHERE id = ? AND user_id = ?
       -> 不存在返回 404
       -> 存在则组装 DbDsn
  -> 使用 db_dsn 时：
       直接使用请求体 DSN
  -> 统一连接测试（任务创建前的 SELECT 1）
  -> 写入 runs.db_dsn_json / datagen_jobs.target_dsn_json
  -> 启动任务
```

## 6. 后端实现拆分

### 6.1 `app/db.py`

- 在 `SCHEMA` 中新增 `mysql_connections` 表。
- 新增函数：
  - `list_connections(user_id)`
  - `get_connection(user_id, connection_id)`
  - `create_connection(user_id, fields)`
  - `update_connection(user_id, connection_id, fields)`
  - `delete_connection(user_id, connection_id)`
- 所有查询强制带 `user_id`，不允许按 `connection_id` 单独查询。

### 6.2 `app/services/connection_manager.py`

新增公共服务，职责：

- 解析 `connection_id` 为 `DbDsn`。
- 提供 `test_dsn(dsn)`，内部封装 `pymysql.connect(...)` + `SELECT 1`。
- 提供安全返回连接列表的 `to_public_connection(row)`，移除 `password`，增加 `has_password`。
- 统一异常处理，错误信息不含密码。

### 6.3 `app/routers/connections.py`

新增路由：

- `GET /connections`：管理页面。
- `GET/POST /api/connections`。
- `GET/PUT/DELETE /api/connections/{id}`。
- `POST /api/connections/{id}/test`。
- `POST /api/connections/test`。

### 6.4 `app/routers/tasks.py` 与 `app/routers/datagen.py`

- 删除各自重复的 `pymysql` 连接测试代码，改为调用 `connection_manager.test_dsn()`。
- 创建任务前先解析 DSN：
  - 有 `connection_id`：调用 `connection_manager.resolve_connection(user_id, connection_id)`。
  - 有 `db_dsn`：直接使用请求体。
- 解析后继续保存 `db_dsn_json` / `target_dsn_json`。

### 6.5 `app/main.py`

- 注册 `connections.router`，同样挂载在 `require_user` 依赖下。

## 7. 前端设计

### 7.1 新增连接管理页 `/connections`

- 侧边栏新增“连接管理”入口。
- 页面主体为当前用户连接列表。
- 支持新建、编辑、删除、测试操作。
- 每条连接展示名称、地址、端口、用户、数据库、更新时间。
- 密码列在编辑表单中展示为占位符；保存时不回填密码。

### 7.2 新建压测页 `/runs/new`

- 表单顶部增加连接模式切换：
  - 已保存连接：下拉选择当前用户的连接，可选“测试连接”。
  - 临时连接：显示原有 DSN 表单。
- 选择已保存连接时不显示 DSN 表单，也不再把 DSN 写入 `localStorage`。
- 可保留“最近选择”的 `connection_id` 存在 `localStorage`，但不再保存密码。
- 提交规则：
  - 已保存连接：提交 `connection_id`，不提交 `db_dsn`。
  - 临时连接：提交 `db_dsn`，不提交 `connection_id`。

### 7.3 造数页 `/datagen`

- 复用与压测页相同的连接模式切换。
- 原造数 DSN 表单保留为“临时连接”模式。
- 已保存连接模式只提交 `connection_id`。
- SQL 和 Shell 两种造数模式共用同一组连接选择。

### 7.4 现有 `localStorage`

- 不再保存明文密码。
- 已有 `localStorage` 中的旧 DSN 可作为一次性迁移数据：
  - 可选在连接管理页提供“从浏览器旧数据导入”。
  - V1 可只清理旧字段，不提供导入。

## 8. 安全与隐私

- NFR-1 连接列表和详情接口不返回 `password`。
- NFR-2 编辑时密码留空表示保持原密码，避免前端把密码反复回传。
- NFR-3 所有连接查询按 `user_id` 过滤，防止越权访问其他用户连接。
- NFR-4 日志、连接错误、页面回显中不得出现密码。
- NFR-5 `test_dsn` 只执行 `SELECT 1`，不执行任意 SQL。
- NFR-6 历史任务快照中的密码沿用现有 SQLite 明文存储方式，V1 不改写；加密由 V2 统一处理。
- NFR-7 沿用户鉴权现状使用会话 Cookie；CSRF 防护的现状与 `auth_design.md` 一致，本设计不额外引入。

## 9. 测试方案

### 9.1 单元测试

- 连接 CRUD 基本行为。
- 同名连接同一用户下冲突，不同用户下允许。
- 用户 A 不能读取、修改、删除用户 B 的连接。
- 编辑连接时密码留空保持旧密码，提交新密码则更新。
- 列表接口不返回 `password`。
- `connection_id` 与 `db_dsn` 同时为空时报 400，同时提供时报 400。
- 使用 `connection_id` 后，任务快照包含正确的 DSN JSON。

### 9.2 集成测试

- 有真实登录用户时创建连接，并用连接创建压测任务和造数任务。
- 连接被删除后，历史任务仍能读取原快照。
- `AUTH_ENABLED=false` 时匿名空间连接可用。
- `/api/connections/{id}/test` 对无权限连接返回错误。

### 9.3 回归测试

- 原有只填 `db_dsn` 的压测、造数请求行为不变。
- 历史任务列表、监控、报告页面不受影响。
- `/api/db/test` 如保留兼容，继续返回相同结构。

## 11. 待确认事项

- 同名连接是否允许重复：V1 默认不允许，可改为允许后依靠名称展示区分。
- 历史任务表是否增加 `connection_id` 追溯列：V1 最小实现可不加。
- 是否保留 `/api/db/test` 兼容接口：建议保留，避免旧页面缓存和外部调用失效。
- 匿名空间连接在重新启用鉴权后如何处理：V1 保持不可见，不自动迁移。
- 密码加密存储：建议 V2 使用 `APP_SECRET_KEY` 派生密钥进行可逆加密，并同步处理历史快照展示。
