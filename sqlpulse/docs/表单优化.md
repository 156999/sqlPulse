# 压测表单优化设计

## 1. 目标与范围

优化“新建压测”页面的表单模式，让用户清楚理解：一个卡片代表什么、组内 SQL 如何执行、参数何时生成、失败时如何处理。

本次设计包括：任务组卡片、执行方式、权重反馈、变量表格、占位符插入、校验预览，以及表单与文本模式切换。保留 SQL 文本编辑，不引入可视化 SQL 拼装器。

本文为本次实现的设计依据。已实现任务组卡片、变量表格、占位符插入、预览接口、模式转换与旧草稿迁移；真实 MySQL 提交与回滚验证需要单独的测试数据库。

后续优化增加“智能占位符补全”：在不改变现有占位符规则的前提下，基于用户 SQL 和目标表字段元数据，为缺少比较操作和值的条件自动补充直接占位符，降低编写压测 SQL 的门槛。

## 2. 核心概念

### 2.1 任务组

一个表单卡片代表一个 SQL 任务组，可以包含一条或多条 SQL，语句用分号分隔。

- 调度器按权重选择整个任务组。
- 一次选中后，组内语句按顺序执行。
- 权重代表任务组被选中的相对概率，不代表 SQL 条数占比或执行时间占比。
- 任务组不等于事务。是否作为事务执行，由执行方式决定。

界面统一使用“SQL 任务组”“添加任务组”，不再用容易被理解为单条语句的“普通 SQL”描述卡片。

### 2.2 占位符与命名变量

| 写法 | 含义 | 生成时机 |
|---|---|---|
| `{{rand(1,10000)}}` | 直接随机占位符 | 每条语句执行前，每个出现位置独立采样 |
| `{{var('order_id')}}` | 命名变量占位符 | 每次任务组执行开始时生成，组内所有引用复用 |

变量定义可被多个任务组引用，但不同任务组执行、不同虚拟用户之间不共享生成结果。下次执行重新采样，不保证值一定与上次不同。

### 2.3 智能占位符补全

智能补全只负责把不完整的条件补成可执行的现有占位符表达式，不自动创建命名变量配置，也不推断跨 SQL 的业务关联。

示例：

```sql
SELECT * FROM orders WHERE id
```

补全为：

```sql
SELECT * FROM orders WHERE id = {{rand(1,10000)}}
```

如果用户需要多条 SQL 复用同一个业务值，例如先查询订单再更新同一订单，仍由用户手动改成 `{{var('order_id')}}` 并在命名变量表格中配置 `order_id = rand(1,10000)`。系统可以提示“多处相同字段使用了独立随机占位符，如需同一业务值请改用命名变量”，但不自动改写为 `var()`。

智能补全遵循以下边界：

- 只生成直接占位符：`{{rand(...)}}`、`{{randf(...)}}`、`{{pick(...)}}`、`{{pickw(...)}}`、`{{randstr(...)}}`、`{{randdate(...)}}`、`{{randdt(...)}}`、`{{uuid()}}` 等。
- 不写入、修改或删除命名变量配置。
- 不跨任务组共享生成值；直接占位符仍按现有规则独立采样。
- 不补动态表名、列名或 SQL 片段，占位符只用于数据值。
- 不静默改写用户已经写完整的条件；补全结果应可预览、可撤销。

字段到默认占位符的推荐规则：

| 字段特征 | 默认补全 |
|---|---|
| 整数主键、索引 ID、外键 ID | `= {{rand(min,max)}}`；若接入真实采样能力，可优先建议 `= {{sample('table','column')}}` |
| 普通整数 | `= {{rand(min,max)}}` |
| 小数金额、价格、比例 | `= {{randf(min,max,digits)}}`，或按语义使用 `>=` / `<=` |
| 低基数字符串、状态、类型 | `= {{pick('a','b','c')}}` |
| 普通字符串 | `= {{randstr(n)}}`；模糊查询场景可提示用户手动调整为 `LIKE` |
| 日期 | `>= {{randdate('YYYY-MM-DD','YYYY-MM-DD')}}` |
| 日期时间 | `>= {{randdt('YYYY-MM-DD HH:MM:SS','YYYY-MM-DD HH:MM:SS')}}` |
| UUID 字段 | `= {{uuid()}}` |
| 可空字段 | 默认不生成 `NULL` 比较；如需空值判断，提示用户手动使用 `IS NULL` |

当缺少真实表元数据时，系统可基于字段名和常见类型做保守补全，例如 `id` 使用整数随机、`status/type` 使用枚举占位符、`created_at/updated_at` 使用时间占位符；无法判断时只提示用户选择占位符类型，不应随意生成高风险表达式。

## 3. 页面结构

页面按以下顺序组织：

1. 压测任务名称与目标数据库。
2. SQL 入口：直接填写表单、从 SQL 文本导入、从 SQL 文件导入。
3. SQL 任务组卡片列表。
4. 命名变量配置表。
5. 并发数、每秒启动用户数、持续时间。
6. 校验与预览、开始压测。

智能占位符补全入口放在 SQL 任务组卡片内，可作为编辑区工具按钮或校验结果中的建议操作。补全前应展示将要替换的 SQL 片段、推荐原因和生成的占位符表达式，用户确认后再应用。

任务组卡片示意：

```text
任务组 1：订单支付                         [折叠] [复制] [删除]

执行方式：[事务执行 ▼]    权重：[70]    预计占比：70%
组内语句全部成功后统一提交，失败时回滚未提交的修改。

SQL
┌──────────────────────────────────────────────────────┐
│ SELECT * FROM orders                                 │
│ WHERE id = {{var('order_id')}};                       │
│                                                      │
│ UPDATE orders SET status = 'paid'                    │
│ WHERE id = {{var('order_id')}};                       │
└──────────────────────────────────────────────────────┘
系统自动添加 BEGIN / COMMIT。

引用变量：order_id
同一次任务组执行内保持一致，下次执行重新生成。
```

## 4. 任务组卡片

### 4.1 字段与操作

| 项目 | 设计 |
|---|---|
| 任务组名称 | 可编辑；默认“任务组 1”“任务组 2”等，用于识别和错误定位 |
| 执行方式 | 必选，默认“逐条提交” |
| 权重 | 必须是大于零的整数；新增组默认 1 |
| 预计占比 | 根据有效任务组权重实时计算，不允许手动编辑 |
| SQL 编辑区 | 支持多条语句，保留光标位置；错误可定位到对应行列 |
| 引用变量 | 展示解析得到的命名变量引用；未定义项明确标记 |
| 折叠 | 保留名称、执行方式、权重、占比及错误状态 |
| 复制 | 复制执行方式、权重和 SQL，名称追加“副本”；使用独立卡片标识 |
| 删除 | 移除卡片并提供短时撤销，避免误删后无法恢复 |

空卡片显示“未填写，提交时忽略”，不参与占比计算。所有卡片为空时禁止开始压测。

### 4.2 权重反馈

计算方式：`本组权重 / 所有非空任务组权重之和 × 100%`。

输入变化或 SQL 由空变为非空时立即更新。展示值可四舍五入，并说明是预计调度占比；实际有限次执行的占比可能有偏差。

非法权重显示字段错误，不静默修正为 1。界面不得把任务组调度占比描述为 SQL 执行条数占比。

## 5. 执行方式

| 选项 | 提交行为 | 中途失败行为 |
|---|---|---|
| 逐条提交 | 组内 SQL 顺序执行，每条成功后提交 | 停止当前任务组，之前已提交的修改保留 |
| 事务执行 | 组内 SQL 顺序执行，全部成功后统一提交 | 停止当前任务组，尝试回滚未提交的修改 |

选择后直接显示对应行为说明，两种方式都支持命名变量复用。

### 5.1 事务边界管理

表单模式由系统统一管理事务边界，编辑区只填写业务 SQL：

```sql
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
```

- 选择“事务执行”时，提交及预览时自动添加一层 `BEGIN / COMMIT`。
- 粘贴内容若恰好包含一组完整的最外层 `BEGIN / COMMIT` 或 `START TRANSACTION / COMMIT`，识别后规范化为事务模式，编辑区移除该外层边界，并提示“已识别事务，边界由系统管理”。允许撤销转换。
- 已有 SQL 与用户选择“逐条提交”发生冲突时，要求先解决冲突，不静默改变提交行为。
- 不自动删除内部事务控制语句。多段事务、嵌套边界、`ROLLBACK`、`SAVEPOINT`、`SET autocommit` 等超出简单表单语义的脚本，保留原文并提示修改后重新导入。
- 识别必须基于 SQL 词法边界，不能因字符串或注释里出现 `BEGIN`、`COMMIT` 而误判。

事务模式提示：回滚能力取决于数据库、存储引擎及语句类型；DDL 等隐式提交语句不保证整体回滚。校验预览对已识别的隐式提交语句给出提示，不宣称预检查覆盖所有数据库行为。

## 6. 命名变量表格

将现有手写“变量名 = 生成规则”文本区替换为独立表格：

| 名称 | 生成类型 | 参数 | 操作 |
|---|---|---|---|
| order_id | 随机整数 | 最小值 1；最大值 10000 | 插入占位符、删除 |
| status | 随机枚举 | pending；paid；cancelled | 插入占位符、删除 |

表格下方提供“添加变量”。说明文案：“定义可被多个任务组引用；每次任务组执行独立生成，组内复用。”

### 6.1 各类型的参数控件

| 生成类型 | 参数控件 | 主要校验 |
|---|---|---|
| 随机整数 | 最小值、最大值 | 整数，下限不大于上限 |
| 随机小数 | 最小值、最大值、小数位数 | 有限数字，精度 0～10，区间内存在合法精度值 |
| 随机枚举 | 可增删的候选值列表 | 至少一项，每项指定值类型 |
| 加权枚举 | 候选值类型、值、权重 | 非负有限权重，合计有限且大于零 |
| 随机字符串 | 长度 | 1～4096 |
| 随机日期 | 开始日期、结束日期 | 有效日期，开始不晚于结束 |
| 随机日期时间 | 开始时间、结束时间，精确到秒 | 有效日期时间，开始不晚于结束 |
| UUID | 无参数 | 无额外输入 |

枚举值类型为字符串、整数、小数、布尔值、空值。字符串 `"1"` 与整数 `1`、字符串 `"None"` 与空值必须区分。候选项使用独立输入行，不用逗号拆分用户文本，确保含逗号和引号的字符串能完整保存。

变量名遵循已有后端规则：1～64 位字母、数字、下划线，不能以数字开头，同一配置中不能重名。生成规则不允许引用其他变量。

前端将控件值序列化为现有生成规则字符串，继续提交：

```json
{
  "variables": {
    "order_id": "rand(1,10000)",
    "status": "pick('pending','paid','cancelled')"
  }
}
```

字符串序列化应正确处理引号、反斜杠和换行，不执行用户输入。前后端共享同一规则契约，后端校验为最终依据。

### 6.2 插入占位符

按钮统一命名为“插入占位符”，不使用含义模糊的“插入 SQL”。

1. 用户在 SQL 编辑区放置光标或选中待替换文本。
2. 点击变量所在行的按钮。
3. 将 `{{var('order_id')}}` 插入最近聚焦的 SQL 编辑框光标处，或替换选中文字。
4. 恢复编辑框焦点，光标移到插入内容之后。

点击按钮导致编辑框失焦时，仍须保留之前的目标卡片、选择范围和光标位置。未选过编辑框或目标已删除时，提示选择目标任务组，不默认写入第一组。

占位符插入只面向任务组表单。文本和文件导入区禁用插入按钮，提示先将内容应用到表单。

按钮只插入引用，不生成固定值、不执行 SQL、不自动给占位符加引号。变量行未通过校验时不可插入。

### 6.3 重命名、删除与引用反馈

- 重命名变量后，在解析器识别的 `var()` 引用位置同步更新；字符串、注释中的相同文字保持原样。
- 若引用同步无法安全完成，保留原 SQL，列出受影响任务组，要求解决后再提交。
- 删除已引用变量时列出引用位置，允许撤销；未解决的引用显示为错误并阻止开始压测。
- 任务组卡片展示它实际引用的变量，不把所有定义都显示为本组引用。

## 7. 校验与预览

页面底部提供“校验与预览”和“开始压测”。预览是可选检查步骤，点击开始压测仍必须执行完整校验，不能依赖此前结果。

### 7.1 校验内容

- 非空任务组、权重合法性、SQL 分句与事务边界冲突。
- 占位符函数、参数类型、范围、精度、日期和权重规则。
- 变量名、重复名称、变量生成规则和未定义引用。
- 已识别的隐式提交语句与事务模式提示。

错误同时展示在顶部摘要和对应卡片或变量行。SQL 错误包含任务组名称、语句序号、行列，点击后聚焦对应位置。

变量使用外层引号的常见误用应提示：“引号内的内容作为普通字符串，不会生成随机值。”该提示不改变原文本，也不把所有含 `{{...}}` 的字符串判为非法。

### 7.2 预览内容

```text
✓ 校验通过
订单支付 · 事务执行 · 2 条业务 SQL · 预计占比 70%

本次示例变量：order_id = 5821
组内两条语句均使用 5821。

执行结构：BEGIN → SQL 1 → SQL 2 → COMMIT
[查看参数化 SQL 与本次参数]  [重新生成示例]

仅展示示例，不执行 SQL；正式压测时重新生成。
```

- 每次预览为每个任务组生成独立变量上下文，复用规则与正式执行相同。
- 直接随机占位符仍在不同位置独立采样。
- 默认展示示例变量和执行结构；展开可查看参数化 SQL 及对应参数列表。
- 不使用 `repr()` 拼接一条貌似可执行的 SQL，避免重新引入引号和类型问题。
- 日期、Decimal 等参数序列化时保留类型信息；空值明确展示为 `NULL`。
- 修改 SQL、变量、权重或执行方式后，标记旧预览已过期。

预览不连接目标数据库，不执行用户 SQL，也不保证数据库表、权限或 SQL 方言合法。

## 8. 统一表单提交与导入草稿

### 8.1 唯一提交入口

文本和文件仅用于导入，不再提供直接开始压测的入口。流程为：

```text
文本或文件 → 解析并预览 → 检查转换摘要 → 应用到任务组表单 → 校验 → 开始压测
```

表单始终提交 `groups + variables`；即便通过键盘触发表单提交事件，处于导入区时也会拒绝提交。旧 `sql_content` API 保留兼容，页面不再使用它创建压测。

### 8.2 转换摘要与应用

解析成功后展示任务组名称、执行方式、权重、业务 SQL 条数、转换后的 SQL、缺失变量及注意事项。尚未定义的变量允许先应用到表单，补全后才能开始压测。

- 表单为空：显示“应用到表单”。
- 表单已有内容：提供“追加到现有表单”和“替换现有表单”。
- 应用时为导入组分配新标识，重新计算调度占比；提供撤销，现有变量配置保留。
- 修改导入原文或配置后，之前的解析结果失效，必须重新解析。
- 全部解析成功后才能应用；失败时不导入其中任何一部分。

### 8.3 不支持的脚本

嵌套事务、多段事务混在一个权重组、SAVEPOINT、手动 autocommit、MySQL 可执行注释等无法完整映射到表单的脚本，保留完整原文并提示修改后重新导入。不再建议从文本模式直接执行，也不自动拆分改变调度语义。

### 8.4 草稿与来源

表单任务组、文本导入原文、文件原文各自保存。切换入口不覆盖表单；文件可显式复制到文本导入区修改，并支持撤销覆盖。示例同样走导入预览流程。

草稿保存变量结构、任务组名称、标识、执行方式、权重、SQL、当前入口和压测参数。兼容旧版表单和文本/文件模式草稿；旧导入原文保留，必须解析并应用后才能提交。

连接密码不写入本地草稿。后端保存的执行内容来自表单，导入原文不作为另一份执行来源。

| 测试及文档 | 覆盖前后端行为、兼容性和操作说明 |

建议新增 `POST /api/runs/preview`，使用与创建压测相同的登录要求，但不要求目标连接。路由应放在 `/api/runs/{run_id}` 等动态路由之前，避免路径冲突。

表单内部使用结构化模型，例如：

```json
{
  "groups": [
    {
      "id": "group-1",
      "name": "订单支付",
      "execution_mode": "transaction",
      "weight": 70,
      "sql": "SELECT * FROM orders WHERE id = {{var('order_id')}};"
    }
  ],
  "variables": {"order_id": "rand(1,10000)"}
}
```

表单预览与创建运行共用结构化组的校验及序列化路径。保留现有 `sql_content + variables` API，供文本模式和既有调用方使用；同一请求不得混用两种 SQL 来源。结构化任务组的名称与执行方式随运行记录保存，旧记录仍可按原 SQL 解析。

智能补全建议接口建议复用连接管理能力读取目标库元数据，但不执行用户 SQL。接口输出建议列表，每条建议包含原始范围、替换后 SQL、字段信息、推荐占位符、置信度和提示文案。应用建议由前端在当前任务组编辑区完成，并进入现有预览与启动校验流程。

## 10. 实施顺序

1. 明确结构化表单模型及兼容协议，实现任务组卡片、执行方式和权重反馈。
2. 实现变量表格、类型控件、占位符插入与引用反馈。
3. 实现后端校验预览接口，接入错误定位和过期状态。
4. 完善模式转换、旧草稿迁移与运行配置持久化。
5. 实现智能占位符补全：字段元数据读取、缺失条件识别、直接占位符推荐、确认应用与撤销。
6. 完成回归验证，同步示例和帮助文案。

## 11. 验收标准

- 一张卡片明确表示一个任务组，多条 SQL 按既定顺序执行。
- 权重占比随编辑实时变化，空卡片不参与计算。
- 逐条提交和事务执行的行为说明准确，事务边界不会重复添加。
- 复杂事务脚本不会在模式转换中被静默改写。
- 变量表格完整覆盖现有 8 种生成函数，类型与特殊字符往返转换正确。
- 插入占位符写入正确的编辑框与光标位置，不覆盖其他任务组。
- 同次组内变量一致，不同任务组执行独立生成；普通随机占位符各位置独立采样。
- 预览不连接数据库、不执行 SQL，修改配置后旧预览明确失效。
- 非法配置能定位到卡片或变量行，点击开始压测仍由后端重新校验。
- 文本和文件必须解析并应用到表单才能提交；失败不部分导入，切换入口不会覆盖现有表单。
- 旧 API、旧运行记录和旧草稿有明确兼容路径。
- 智能补全只生成直接占位符，不自动创建或修改命名变量配置。
- 智能补全不会静默改写完整条件，建议应用前可预览、应用后可撤销。
- 多处相同字段被补为独立直接占位符时，可提示用户按需改为命名变量，但系统不自动推断业务关联。
- 使用模拟执行验证失败时停止后续语句和事务回滚；使用测试 MySQL 验证逐条提交与事务提交的实际差异。


## 12. 本次实现与验证入口

- 页面脚本：`app/static/run_form.js`；公共表单服务：`app/services/run_form.py`。
- `POST /api/runs/preview`：共用创建运行的校验路径，返回类型化示例参数，不连接数据库。
- `POST /api/runs/form-tools`：执行 SQL 转换、表单序列化、事务识别、旧变量配置转换、引用分析及重命名。
- `runs.groups_json` 保存任务组名称、标识和执行方式，旧记录默认为空列表；运行时优先使用已保存结构。
- Python 回归：`.venv/Scripts/python.exe -m pytest tests/unit -q`。
- 前端逻辑回归：`node --test tests/frontend/run_form.test.cjs`。
- 可选真实数据库测试：配置 `SQLPULSE_TEST_MYSQL=1` 和 `TEST_MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` 后运行 `tests/integration/test_form_mysql.py`。测试仅使用连接内临时表，验证重复主键失败时两种执行方式的提交差异，以及后续语句不会继续执行。
- 导入转换采用保守规则：MySQL 可执行注释及复杂事务脚本保留原文并阻止导入，须修改后重新解析。
- `form-tools` 新增 `action: "import"`，返回转换摘要与缺失变量引用，不连接数据库、不写入运行记录。
