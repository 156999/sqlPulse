# 造数增强设计

## 目标

造数配置不再只描述“如何生成一个值”，还要能表达目标表的真实约束和数据分布。系统在提交造数任务前读取数据库元数据，在生成过程中校验约束，并支持从已有数据抽样后再组合生成，降低插入失败率，使新增数据接近现有分布。

## 一、数据模型

### 1. 字段规则

每个字段增加规则对象：

```json
{
  "column": "email",
  "generator": "random_string",
  "length": {"min": 8, "max": 64},
  "nullable": false,
  "unique": true,
  "pattern": "^[a-z0-9._%+-]+@[a-z0-9.-]+\\.[a-z]{2,}$",
  "default_policy": "omit",
  "distribution": {"mode": "weighted", "sample_size": 10000}
}
```

规则来源分为三类，优先级依次为：用户显式配置、数据库元数据、生成器默认值。用户配置不能突破数据库硬限制；例如 `max_length=20` 时，生成器最长只能取 20。

### 2. 数据库约束

自动读取并展示：

- 字符串、二进制、数值、日期时间字段的类型和长度/精度/小数位。
- `NOT NULL`、默认值、自动更新时间。
- 主键、唯一索引、联合唯一索引。
- 外键及被引用表、列。
- `CHECK` 约束（数据库支持时）。
- 枚举、集合、生成列和自增列。

页面提供“刷新表结构”和“应用数据库限制”按钮，并显示规则来源。无法读取的约束必须标记为“未识别”，不能假设可插入。

## 二、表单设计

### 1. 造数对象

在现有 SQL/变量配置下增加“目标表字段规则”模式。选择表后展示字段表格：

单表 INSERT 场景提供独立的“单表表单”模式：用户只需输入目标表并点击“读取表结构”，系统自动读取列名、数据库类型、长度、非空、默认值和自增信息，生成可编辑的字段列表。自增列、生成列和默认值列默认跳过，提交时由系统生成标准 INSERT SQL，继续复用现有 SQL 参数绑定和任务执行链路。

| 字段 | 类型/限制 | 生成方式 | 参数 | 唯一性 | 空值比例 | 数据来源 |
|---|---|---|---|---|---|---|

生成方式包括随机值、序列、固定值、枚举、引用变量、已有数据抽样、按分布抽样。单表表单中的“已有数据抽样”默认从目标表同名字段读取，用户只设置样本比例；未命中样本的部分由系统根据字段类型自动选择随机生成器。自增列、生成列和有默认值的列默认不生成，除非用户显式开启覆盖。

### 2. 校验反馈

提交前执行静态校验：长度、精度、必填、枚举值、正则、唯一键组合、外键来源和生成条数。错误定位到字段和规则；可修复问题给出建议，例如“生成条数超过可用唯一值空间”。

### 3. 单表表单规则归一化

“应用数据库限制”不是只读校验，而是将用户配置与数据库硬限制取交集，并把可安全修复的结果回写到单表字段表单。按钮执行前保留用户原始规则，执行后展示修改明细；用户可继续编辑或恢复单个字段。

规则优先级为：

```text
数据库硬限制 > 用户显式配置 > 已有数据统计/sample > 类型默认规则
```

数据库硬限制不能被用户配置突破。数据库未限制的部分继续保留用户配置，不应为了统一格式覆盖用户选择。

字段表格扩展为：

| 字段 | 数据库类型/限制 | 生成方式 | 用户参数 | 应用后参数 | 规则状态 | 操作 |
|---|---|---|---|---|---|---|
| age | tinyint unsigned / CHECK 1～20 | 随机整数 | 1～999 | 1～20 | 已调整 | 恢复 |
| nickname | varchar(20) | 随机字符串 | 长度 100 | 长度 20 | 已调整 | 恢复 |
| amount | decimal(10,2) | 随机小数 | 0～999999999 / 4 位 | 0～99999999.99 / 2 位 | 已调整 | 恢复 |

用户可编辑的参数至少包括：

- 整数和小数：最小值、最大值、小数位。
- 字符串和二进制：最小长度、最大长度、字符集或内容模板。
- 日期时间：开始时间、结束时间。
- 枚举：候选值及权重。
- 空值：空值比例。
- sample：样本比例、抽样模式；来源固定为当前目标表同名字段。
- 唯一字段：生成策略、冲突重试次数。

### 4. 自动修正规则

点击“应用数据库限制”后按字段执行以下归一化：

| 数据库约束 | 用户配置 | 自动处理 |
|---|---|---|
| 整数类型范围或数值 CHECK | 随机范围超界 | 将上下限收缩到合法交集；交集为空时报错 |
| `decimal(p,s)` | 范围或小数位超界 | 最大整数位限制为 `p-s`，小数位收缩到 `s` |
| `varchar(n)` / `char(n)` | 字符串长度超过 `n` | 最大长度改为 `n`；最小长度大于 `n` 时改为 `n` 并标记警告 |
| `enum` | 候选值包含非法值 | 移除非法候选值并重新归一化权重；无候选值时报错 |
| `set` | 候选组合包含非法成员 | 移除非法成员；空组合按空值/default 规则处理 |
| `NOT NULL` | 空值比例大于 0 | 空值比例改为 0 |
| `DEFAULT` | 用户未显式覆盖 | 生成方式改为“跳过”，由数据库填写默认值 |
| `AUTO_INCREMENT` / 生成列 | 任意生成规则 | 强制改为“跳过” |
| 日期时间精度和 CHECK | 时间范围或精度超界 | 收缩范围并截断到数据库支持的精度 |
| 单列唯一索引 | 普通随机或 sample | 切换为去重随机、序列或 UUID；纯 sample 不允许直接重复使用 |
| 联合唯一索引 | 仅部分字段参与去重 | 对完整字段组合建立任务级去重键 |
| 外键 | 随机生成 | 默认改为从被引用表、列抽样；无可用父记录时报错 |
| 简单跨字段等式 CHECK | 派生字段独立随机 | 将派生字段改为数据库计算规则，并复用本行依赖字段的生成值 |

`CHECK` 约束仅自动处理可安全解析的表达式，包括数值上下界、`IN` 候选集合、字符串长度、日期范围，以及 `目标字段 = 字段四则运算` 形式的简单派生等式。例如 `line_amount = unit_price * quantity - discount_amount` 会让 `line_amount` 复用同一 INSERT 行的价格、数量和优惠值计算，不再独立随机。包含函数、条件分支、子查询或无法安全识别的复杂跨列表达式仍标记为“未识别”，只在执行前提示，不进行猜测性修改。

### 5. sample 与随机比例

单表表单中的 sample 不要求用户填写来源表、来源列或随机表达式：

- 来源表为当前目标表。
- 来源列为当前字段。
- 用户只填写样本比例 0～100。
- 未命中 sample 的比例使用“应用数据库限制”后的随机规则。
- `sample_ratio=100` 时为纯抽样；唯一字段不允许纯抽样，除非启用任务级不放回抽样且样本数量足够。
- 来源字段无数据时，比例低于 100 的任务全部使用随机规则；比例为 100 时阻止提交并提示无可用样本。

示例：用户为 `age` 配置随机范围 1～999，数据库规则将其归一化为 1～20，随后设置 sample 比例为 70%。最终行为为 70% 从当前表 `age` 抽样，30% 使用 `rand(1,20)`。

### 6. 差异反馈与交互

应用完成后，页面顶部显示汇总：

```text
已应用 12 个数据库规则：调整 4 个字段，跳过 2 个字段，1 个字段需要处理。
```

每项变更必须显示原值、应用值和原因，例如：

```text
age：随机范围 1～999 -> 1～20（受 CHECK age BETWEEN 1 AND 20 限制）
nickname：最大长度 100 -> 20（受 varchar(20) 限制）
amount：小数位 4 -> 2（受 decimal(10,2) 限制）
user_id：随机整数 -> 外键抽样（引用 users.id）
```

规则状态分为：`未应用`、`已通过`、`已调整`、`警告`、`错误`、`未识别`。错误字段阻止提交；警告和未识别字段允许用户确认后继续。再次点击按钮必须基于当前用户配置重新计算，结果应幂等，不能重复收缩或累计修改。

### 7. 前后端接口

规则应用接口：

```http
POST /api/datagen/rules/apply
```

请求示例：

```json
{
  "connection_id": "conn-id",
  "table": "users",
  "row_count": 1000,
  "rules": [
    {
      "column": "age",
      "generator": "rand",
      "params": {"min": 1, "max": 999},
      "null_ratio": 0,
      "sample_ratio": 70
    }
  ]
}
```

响应示例：

```json
{
  "ok": true,
  "rules": [
    {
      "column": "age",
      "generator": "sample_mix",
      "params": {"min": 1, "max": 20},
      "sample_ratio": 70,
      "sample_source": {"table": "users", "column": "age"},
      "status": "adjusted"
    }
  ],
  "changes": [
    {
      "column": "age",
      "path": "params.max",
      "before": 999,
      "after": 20,
      "reason": "CHECK age BETWEEN 1 AND 20"
    }
  ],
  "errors": [],
  "warnings": []
}
```

服务端必须重新读取数据库元数据并完成归一化，不能信任浏览器提交的字段类型和限制。创建任务时再次执行同一套归一化和校验，防止读取表结构后数据库发生变更，或请求绕过页面直接提交非法规则。

## 三、已有数据抽样与分布保持

### 1. 抽样策略

新增 `sample(table, column, options)` 占位符，支持：

- `uniform`：等概率抽样。
- `weighted`：按值频次加权抽样，保留热门值比例。
- `recent`：按时间列优先抽取近期数据。
- `where`：限定抽样条件。

变量编辑器新增“已有数据抽样”生成类型。抽样变量可设置样本比例和随机生成表达式：

- `sample_ratio`：每次使用已有数据样本的概率，范围 0～100，默认 100。
- `random`：当样本未命中时使用的随机生成表达式，例如 `rand(1,10000)`。
- 比例为 100 时为纯抽样；比例为 0 时为纯随机；中间值按每次生成独立随机选择。
- 随机表达式必须与目标字段类型兼容，且同样经过占位符安全校验。

示例：

```sql
INSERT INTO orders(user_id, city, amount)
VALUES (
  {{sample('users', 'id', {'mode':'weighted'})}},
  {{sample('users', 'city', {'mode':'weighted'})}},
  {{randf(10, 500, 2)}}
)
```

混合生成示例（70% 使用已有用户 ID，30% 使用随机 ID）：

```sql
{{sample('users', 'id', {'sample_ratio': 70, 'random': 'rand(1,100000)'})}}
```

### 2. 采样缓存

任务开始时按表/列/条件生成受控样本集，默认最多 10,000 行，任务内复用缓存，避免每条 INSERT 查询数据库。缓存只读、带连接和条件指纹；任务结束清理。唯一字段不能直接重复抽样，需启用去重或改用序列生成。

### 3. 分布统计

对数值字段保存分位点、均值、标准差和空值比例；对枚举/字符串保存频次 Top-N。默认只保存脱敏后的统计信息，不落盘原始敏感值。用户可选择“仅统计”“抽样值”“不读取已有数据”。

## 四、唯一性、关联和事务

- 单列唯一：维护任务级已用集合；批量预留值并在冲突时重试，超过阈值直接失败并报告可用空间。
- 联合唯一：对完整列组合计算键后去重，不能只保证单列唯一。
- 主外键：先生成父表数据或从父表抽样，再生成子表；提供级联任务顺序。
- 事务模式：按批次提交，默认每 500 条提交一次；失败批次回滚并记录冲突样例。
- 并发造数时使用数据库唯一索引作为最终裁判，应用层校验仅用于减少冲突。

## 五、执行流程

1. 连接数据库并读取元数据。
2. 将 SQL、变量表和字段规则编译为统一的生成计划。
3. 预计算约束、唯一空间、外键顺序和抽样缓存。
4. 生成一小批预览数据，执行本地规则校验；用户可查看失败原因。
5. 按批次生成、绑定参数并插入，记录成功数、冲突数和重试数。
6. 任务结束输出约束覆盖率、分布对比和未满足规则。

## 六、兼容与安全

- 现有 `rand/randf/pick/randstr/randdate/randdt/uuid/var` 继续兼容。
- 新增 `sample` 只允许读取用户选择的表和列，禁止拼接未经校验的表名、列名和条件。
- 默认不读取密码、token、身份证号等敏感列；敏感列必须显式确认并支持脱敏抽样。
- 抽样查询设置行数、超时和权限边界，禁止全表扫描；大表优先使用索引、近似统计或分层抽样。

## 七、分阶段实施

1. **可编辑单表规则**：在读取表结构后展示并保存每个字段的生成方式、范围、长度、精度、空值比例和 sample 比例。
2. **基础规则归一化**：实现数值范围、字符串长度、精度、枚举、非空、默认值、自增列和生成列的自动修正及差异反馈。
3. **唯一性和外键计划**：实现单列/联合唯一去重、外键自动抽样、父子表顺序和批量重试。
4. **抽样占位符**：实现受限样本缓存、均匀/加权抽样、权限控制和随机/样本比例混合模式。
5. **分布保持**：增加统计、分位点和预览对比，支持按字段选择分布策略。

验收标准：

- 常见 MySQL 表结构可自动识别 95% 以上的字段硬约束。
- 用户配置超出数值范围、字符串长度或小数精度时，应用数据库限制后自动收缩到合法交集，并展示修改前后值。
- `NOT NULL`、枚举、默认值、自增列和生成列规则可正确更新表单配置。
- 单列唯一、联合唯一和外键字段在执行前形成明确生成计划，无法满足时阻止提交。
- 单表 sample 只要求用户设置比例，来源自动绑定当前表同名字段，随机部分使用归一化后的字段规则。
- 相同输入和相同数据库结构重复应用规则，输出完全一致。
- 创建任务时服务端复验规则，不能通过绕过页面提交突破数据库硬限制。
